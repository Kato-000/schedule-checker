# 予定チェッカー

予定を書くと、ローカルLLMが日時を読み取ってカレンダーに入れる案を作り、準備のTodoも考えます。
内容を確認・修正して承認すると登録され、直した内容は次回の手本になります。
毎朝、今日の予定とやることをまとめて通知し、画面の端に常に最前面のウィジェットを表示します。

予定に結びつかないTodo（「牛乳を買う」など）も、入力欄を「Todo」に切り替えて登録できます（期限なしも可）。

**ネット連携（初期状態はOFF）**：予定に足りない場所・住所・時刻をネットで調べたり、「何時に家を出れば間に合うか」を経路検索で調べたりできます。ボタンを押したときだけ通信します（詳しくは「ネット連携」の章）。

第3段階で、次の2つが加わりました。

- **音声入力**：入力欄のマイクボタンを押して話すと、PCの中で文字にして、そのままLLMに渡して承認待ちに入れます（スマホからも使えます）。録音は保存しません
- **ウィジェットの自動たたみ**：画面の左右・上の端に寄せると、使っていない間は小さなつまみになります。マウスを乗せると開きます。次に起動したときは前回の場所に出ます

第2段階で加わった3つ（どれも初期状態はOFFで、使う場合だけ設定します）：

- **スマホから開く**：自宅のWi-Fiにつながったスマホから、同じ画面を使えます（HTTPS・PINでログイン・インターネットには非公開）
- **Googleカレンダー連携**：取り込みのみ／双方向。予定ごとに「ローカル限定」にしてGoogleに送らないこともできます
- **自分ルール**：承認時の修正から、くり返し出てくる傾向をLLMがルールの案にします。確認してから有効にします

予定データとLLMの処理、音声の文字起こしは、自分のPCの中で完結します。Googleカレンダー連携をONにした場合だけ、予定（タイトル・日時・場所）がGoogleとやり取りされます。ネット連携をONにした場合は、ボタンを押したときだけ、検索語（Web検索）や住所の位置・到着したい時刻（経路検索）が送られます。Todo・修正の記録・LLMの処理内容は送りません。

## 構成

```
schedule-checker/
├─ backend/                 Python（FastAPI）。データ・LLM・朝のまとめ・同期
│   ├─ app/                 本体
│   ├─ tests/               自動テスト
│   ├─ seed_examples.json   初期手本と初期ルール（編集してOK）
│   ├─ requirements-voice.txt  音声入力の部品（faster-whisper）
│   ├─ setup_backend.bat    準備（新しい段階に更新したときも再実行）
│   └─ start_backend.bat    手動で起動（動作確認用）
├─ frontend/                Svelte の画面
│   └─ src-tauri/           Tauri（ウィジェットとメイン画面のアプリ）
├─ register_autostart.ps1   ログオン時の自動起動を登録
├─ make_lan_cert.ps1        スマホ用の証明書を作る
└─ allow_lan_firewall.ps1   スマホ用の入口をファイアウォールで許可（管理者）
```

| 入口 | 使う人 | 認証 |
| --- | --- | --- |
| `http://127.0.0.1:8765` | PCのアプリ（このPCの中だけ） | なし |
| `https://<PCのIP>:8766` | 自宅LANのスマホ（設定でONにしたときだけ開く） | PIN |

## 前の段階から更新するとき

1. 新しいファイルで上書きする（`backend\data` フォルダは残す。予定などのデータはここにあり、自動で新しい形に移行されます）
2. バックエンドを止めて（タスクトレイのアプリはそのままでOK）、`backend\setup_backend.bat` を再実行（音声入力や祝日の計算の部品が追加されます）
3. `cd frontend` → `npm install` → `npm run tauri:build` → できたインストーラー（`ScheduleChecker_0.4.10_x64-setup.exe`）で上書きインストール
   - 第3段階では Tauri 2.12 以降が必要なため、初回のビルドで Rust の部品の更新が入り、少し時間がかかります
4. バックエンドを起動し直す（自動起動を登録済みならPCの再起動でもOK）
5. メイン画面の「設定 > 音声入力」で、文字起こしのモデルをダウンロードする

## セットアップ

### 1. バックエンド

```bat
cd backend
setup_backend.bat
start_backend.bat
```

`Uvicorn running on http://127.0.0.1:8765` と出れば起動しています。

### 2. 画面とウィジェット

```powershell
cd frontend
npm install
npm run tauri:build
```

できたインストーラーを実行します。

```
frontend\src-tauri\target\release\bundle\nsis\ScheduleChecker_0.4.10_x64-setup.exe
```

署名のないアプリなので、Windows の警告（SmartScreen）が出たら「詳細情報」→「実行」を選んでください。

### 3. 自動起動の登録

```powershell
powershell -ExecutionPolicy Bypass -File register_autostart.ps1
```

バックエンドは画面なしで常駐します（ログは `backend\data\backend.log`）。解除は `-Remove` を付けて実行します。

## スマホから開く（自宅LAN内）

スマホのブラウザでマイク（第3段階の音声入力）を使えるようにするため、HTTPS で開きます。そのための証明書を、このPCの中だけで作ります。

1. **証明書を作る**（PCのIPアドレスが変わったときも再実行）
   ```powershell
   powershell -ExecutionPolicy Bypass -File make_lan_cert.ps1
   ```
   最後に表示される手順で、`rootCA.pem` をスマホに入れて信頼する設定にします。
   - iPhone：ファイルを開いてプロファイルをインストール →「設定 > 一般 > 情報 > 証明書信頼設定」で mkcert をオン
   - Android：「設定 > セキュリティ > 暗号化と認証情報 > 証明書のインストール > CA証明書」
   - 一緒にある `rootCA-key.pem` は、絶対にスマホや他の人に渡さないでください
2. **ファイアウォール**：PowerShell を「管理者として実行」して
   ```powershell
   powershell -ExecutionPolicy Bypass -File allow_lan_firewall.ps1
   ```
   自宅のネットワークが「パブリック」になっていると接続できないので、「プライベート」にしてください（スクリプトが案内します）。
3. **PINとON**：メイン画面の「設定 > スマホから開く」で PIN（6文字以上）を決めて「オンにする」。表示されたURLをスマホで開き、PINでログインします。

安全のための仕組み：

- 自宅LAN（プライベートアドレス）以外からの接続は拒否します。ルーターのポート開放はしないでください
- PINを5回間違えると、その端末は15分間ログインできません
- ログインは14日で切れます。PINを変えると、すべてのスマホがログアウトされます
- スマホからは、LAN・Googleの設定は変更できません（PCからだけ）

## Googleカレンダー連携の準備

Googleの「OAuthクライアント」という、このアプリ専用の認証用ファイルを自分で作ります（15分ほど・無料）。画面の名前は変わることがあるので、近い項目を選んでください。

1. https://console.cloud.google.com/ を開き、新しいプロジェクトを作る（名前は例えば `ScheduleChecker`）
2. 「APIとサービス」→「ライブラリ」で **Google Calendar API** を検索して「有効にする」
3. 「OAuth 同意画面」（Google Auth Platform）を設定
   - ユーザーの種類：**外部**
   - アプリ名・サポートメール・連絡先：自分の名前とGmail
   - 「対象」または「テストユーザー」に、自分のGmailアドレスを追加
4. 「認証情報」（クライアント）→「OAuth クライアント ID を作成」
   - アプリケーションの種類：**デスクトップアプリ**
   - 作成後、**JSONをダウンロード**
5. 予定チェッカーの「設定 > Googleカレンダー連携」で、ダウンロードしたJSONファイルを選ぶ →「Googleに接続」
   - ブラウザが開くので、自分のアカウントでログインして許可します
   - 「このアプリは Google で確認されていません」と出たら、自分で作ったアプリなので「詳細」→「（安全ではないページ）に移動」で進めます
6. 連携のしかたを選ぶ：**取り込みのみ**から始めて、問題なければ**双方向**にするのがおすすめです

注意：同意画面の公開ステータスが「テスト」のままだと、Googleの仕様で**7日ごとに接続が切れます**。切れたら設定画面から「Googleに接続」し直すか、公開ステータスを「本番環境」に変更してください（自分だけで使う分には、Googleの審査は不要です）。

連携の動き：

- 自動で同期する間隔を「設定 > Googleカレンダー連携」で選べます：15分ごと（初期値）／1時間ごと／6時間ごと／**1日1回**（朝のまとめの10分前。PCを起動したときにその日まだ同期していなければ起動後すぐ1回）／自動で同期しない。「今すぐ同期」はいつでも使えます。初回は30日前からの予定を取り込みます
- 双方向のときは、こちらで作った・直した・消した予定は間隔にかかわらずすぐGoogleに送ります
- Googleで新しく入った30日以内の予定には、Todoの案を作って承認待ちに出します（予定そのものはすぐカレンダーに入ります）
- 双方向では、こちらで作った・直した・消した予定がGoogleにも反映されます。「ローカル限定」の予定は送りません（予定ごとに、または設定で「新しい予定は最初からローカル限定」）
- 同じ予定がPCとGoogleの両方で変わったときは、承認待ちに「どちらを残すか」が出ます。選ぶまでは、どちらにも上書きしません
- Googleで消えた予定にPC側の未完了のTodoがある場合も、消してよいか確認します
- 認証情報は Windows の資格情報マネージャーに保存します。「接続を解除」で削除されます

## 音声入力

1. メイン画面の「設定 > 音声入力」でモデルを選び、「ダウンロード」を押す（最初の1回だけ。インターネットが必要です）
   - **精度優先**（約1.6GB）：おすすめ。10秒ほどの話で数秒かかります
   - **速さ優先**（約480MB）：速いが、固有名詞などの聞き間違いが増えます
2. 入力欄の左で「予定」か「Todo」を選び、マイクボタンを押して話す。話し終わって少し黙ると自動で止まります（もう一度押しても止まります。Escでやめる）
3. 聞き取った内容はそのままLLMに渡り、承認待ちに案が届きます。聞き取った文は案の上に表示されるので、聞き間違いや読み取りの違いはそこで直して承認します
   - 「予定」を選んでいたとき：いつもの予定の案（準備のTodo付き）
   - 「Todo」を選んでいたとき：予定に結びつかないTodoの案（内容・期限・優先度を直して承認）。文字で入れたTodoと違い、承認するまで登録されません

しくみと注意：

- 文字起こしはPCのCPUで行います（GPUはLLMが使うため）。音声はPCのバックエンドにだけ送られ、保存しません
- モデルは `backend\data\models` に置かれます。ダウンロード後は通信しません
- 最近の予定の名前を手がかりに渡すので、よく使う固有名詞（病院名・会社名など）は聞き取りやすくなります
- マイクが使えないとき：Windowsの「設定 > プライバシーとセキュリティ > マイク」で「デスクトップ アプリがマイクにアクセスできるようにする」をオン
- スマホから使うときは、HTTPS（`https://<PCのIP>:8766`）で開いている必要があります。初回はブラウザがマイクの使用を確認します

## ウィジェットの自動たたみ

- ウィジェットを画面の左・右・上の端に寄せると（端から十数ピクセル以内）、端にぴったり付きます
- マウスがウィジェットから離れて1秒ほどたつと、今日の日付と今日までのTodoの数だけの小さなつまみになります。マウスを乗せると開きます
- 入力欄に文字を入れている間や録音中は、たたみません
- 「設定 > ウィジェット」でオフにできます

## ネット連携（足りない情報を調べる・家を出る時刻）

予定に足りない情報をネットで調べたり、家を出る時刻を経路検索で調べたりします。**自動では通信せず、ボタンを押したときだけ**通信します。送った内容は「設定 > ネット連携 > 外に送った内容の記録」で確認できます。

### 準備（無料のアカウントとAPIキー）

1. **Web検索（Ollama）**：https://ollama.com でアカウントを作り、設定の「API keys」でキーを作る
2. **経路検索（NAVITIME・RapidAPI経由）**：https://rapidapi.com でアカウントを作り、次の3つのAPIでそれぞれ無料の「Basic」プランに登録する（月500回まで）
   - NAVITIME Route(totalnavi)（電車・バスの経路）
   - NAVITIME Route(car)（車の経路）
   - NAVITIME Geocoding（住所から位置を調べる）

   どれかのAPIのページで「X-RapidAPI-Key」の値（キー）をコピーします（3つとも同じキーです）
3. 予定チェッカーの「設定 > ネット連携」で
   - 「ネット連携を使う」をオン
   - 2つのキーを入れて保存（キーはWindowsの資格情報マネージャーに保存されます）
   - 自宅の住所を入れて「確認して保存」（住所検索で位置を確かめます）
   - ふだんの移動手段（電車・バス／車）、何分前に着きたいか、家を出る何分前に通知するかを決める

### 足りない情報を調べる

- 承認待ちの案や、予定の詳細（今日の画面・週・月で予定をクリック）にある「ネットで場所や時刻を調べる」を押す
- **送る検索語が先に表示される**ので、確かめてから「この内容で検索する」。日時やほかの予定は送りません
- 検索結果はこのPCのLLMが読み、住所・開始/終了時刻・場所の名前の**候補**を出します。「反映」を押したものだけが入ります。根拠のページも表示します
- 調べた住所は予定の「住所」欄に入り、経路検索に使われます

### 家を出る時刻

- 予定の詳細の「何時に出ればいいか調べる」を押し、移動手段を選んで「経路を調べる」
- 「開始時刻 − 何分前に着きたいか」に着く経路のうち、いちばん遅く出られるものを選び、「14:12 に出発」のように表示します。乗り換えの流れ・運賃も出ます
- 出発時刻は、今日の画面・ウィジェット・朝のまとめの通知にも出ます。設定した分数前にWindowsの通知でも知らせます
- 送るのは、自宅と目的地の位置（緯度・経度）、目的地の住所（または場所の名前）、到着したい時刻です。予定の名前は送りません
- 予定の日時・場所・住所を変えると、調べた経路は消えます（調べ直してください）。電車の遅れは反映されません

### 地図（Google マップをアプリの中に表示）

- 予定の詳細と承認待ちの案に「地図で見る」「自宅からの経路（地図）」と「地図で探す」欄が出ます。外部のブラウザは開かず、画面の中に Google マップを表示します
- 地図の中で「電車・バス」「車」「場所」を切り替えられます。「地図で探す」に入れた言葉（例：近くの駐車場）の検索結果も地図に出ます
- 地図を開いたときに、場所・住所（経路なら自宅の住所も）と検索した言葉が Google に送られます。送った内容は地図の下と「外に送った内容の記録」に出ます
- 準備：Google Cloud（https://console.cloud.google.com/）で
  1. プロジェクトを作る（Googleカレンダー連携で作ったものを使ってもOK）
  2. 「APIとサービス > ライブラリ」で **Maps Embed API** を有効にする（無料・回数無制限。Google Maps Platform の利用開始時に、お支払い情報の登録を求められることがあります）
  3. 「認証情報 > 認証情報を作成 > APIキー」でキーを作り、「APIの制限」で Maps Embed API だけに絞る
  4. 予定チェッカーの「設定 > ネット連携 > 地図のキー」に入れて保存
- 自宅の住所は、経路検索（NAVITIME）のキーがなくても保存できます（地図の経路表示に使います）

### うまくいかないとき

- 「キーが正しくないか、利用登録がされていません」：RapidAPIで3つのAPIそれぞれのBasicプランに登録したか確認
- 「位置が分かりませんでした」：住所を番地まで入れるか、「ネットで調べる」で住所を探す（施設名だけでは位置を調べられないことがあります）
- RapidAPIの接続先の名前が変わった場合は、環境変数 `SC_NAVI_GEO_HOST` / `SC_NAVI_TRANSIT_HOST` / `SC_NAVI_CAR_HOST` で変更できます

## 自分ルール

- メイン画面の「ルール」で、Todoを作るときにLLMへ渡すルールを管理します
- 修正ありの承認が5件たまるごとに、LLMがくり返し出てくる傾向（例：会議のTodoで毎回「議事録」を消している）からルールの案を作ります。「今すぐ案を作る」でも作れます
- 案は「有効にする／直す／却下」を選びます。却下した内容は、また案として出てきません
- ルールは「全般」か、種類（会議・通院など）ごとに決められます。初期ルール（5件）も、止めたり直したりできます

## 使い方

- **ウィジェット**：今日の予定と、今日までにやることを表示します。チェックを入れると完了。上部の日付部分をドラッグして移動できます
  - 右上のボタン：メイン画面を開く／最前面の固定・解除／たたむ／隠す
  - 隠したウィジェットは、タスクトレイのアイコンをクリックすると戻ります
- **予定の入力**：入力欄の左を「予定」にして、普段の言葉で書きます。承認待ちの画面が開き、数秒で予定が、続けてTodoが表示されます
- **Todoだけを入れる**：入力欄の左を「Todo」にして書きます（例：「金曜までに見積もりを送る、急ぎ」「牛乳を買う」）。予定には結びつかず、承認なしですぐ登録されます
  - 期限と優先度はLLMが文から読み取ります。期限が書かれていなければ「期限なし」になります
  - 登録すると入力欄の下に内容が出るので、「直す」で期限・優先度を変えたり、「取り消す」で消したりできます
  - 期限なしのTodoは、今日の画面の「期限なしのTodo」と、ウィジェットの「期限なしのTodo」に並びます
  - あとから直すときは、今日の画面のTodoの「直す」を押します
  - Ollamaが動いていないときは、入力した文のまま期限なしで登録します
- **承認**：日時・種類・Todo を直して「承認して登録」。日付を変えたら「日付に合わせてTodoを作り直す」
- **メイン画面**：今日／週／月／承認待ち／ルール／設定
- **週・月の表示**：スクロールでずらしながら見られます
  - 週：画面に7日分を出し、横スクロールで前後の日へ流れるように移動します（左ボタンまたは右ボタンでつかんでドラッグ、トラックパッドの左右、Shift+ホイール、下の横スクロールバー、左右スワイプ、←→キーで1日ずつ、PageUp/PageDownで7日ずつ。ドラッグは勢いよく離すと少しすべります）。日付の見出しと時刻の列は固定表示。上下のスクロールは時間帯の移動
  - 月：画面に6週分を出し、縦にスクロールして前後の週へ流れるように移動します（ホイール、マウスの左ボタンまたは右ボタンでつかんで上下にドラッグ、上下スワイプ、↑↓←→キーで1週ずつ、PageUp/PageDownで4週ずつ）。見ている月以外の日は薄く表示。1日に入りきらない予定は「他◯件」
  - 休みの日は色を変えて表示します：土曜は青、日曜と祝日は赤みのある色。祝日は名前も出ます（月は日付の横、週は日付の下）
    - 祝日（振替休日・国民の休日を含む）は PC の中で計算します（jpholiday。ネットには出ません）
  - カレンダーの上では右クリックのメニューは出ません（右ボタンでつかんで動かすため）
  - 上の ‹ › ボタンは、週は7日ずつ、月は前後の月へ。「今日」で戻ります
- **朝のまとめ**：設定の時刻（初期値 7:00）に作られ、Windows の通知で届きます
- **終了**：タスクトレイのアイコンを右クリック →「終了」。×ボタンでは隠れるだけです

## 使っていないときは軽くする

- 操作（マウス・キー・タッチ）がないまま **1分**（「設定 > 動作の軽さ」で30秒〜30分に変更可）たつと、次のように軽くなります
  - LLM（Ollama）のモデルをGPUから外す。文字起こしのモデルもメモリから外す
  - 画面の自動更新（予定・承認待ち・LLMの状態の確認）を止める。隠しているメイン画面も同じ
  - ウィジェットは、画面端にたたんでいる間はマウス位置の確認もしない（つまみにマウスが来たら再開）
- 操作するとすぐ最新の表示に戻ります。日付が変わったときだけは、待機中でもウィジェットを1回読み直します
- 入力欄に文字を入れ始めた時点でLLMの読み込みを始め、マイクを押した時点で文字起こしのモデルの読み込みを始めるので、待ち時間は短くなります（久しぶりの最初の1回は、PCによって数秒〜十数秒かかります）
- 朝のまとめ・Google同期・出発の通知など、決まった時刻の処理は待機中も動きます（必要なときだけLLMを読み込みます）

## 困ったとき

| 症状 | 対処 |
| --- | --- |
| 「バックエンドに接続できません」 | `start_backend.bat` で起動し、エラーが出ていないか確認 |
| メイン画面左下が赤い（LLM） | Ollama が起動していないか、モデルが未取得。`ollama list` で確認 |
| 案が「エラー」になる | 承認待ちに理由が表示されます。却下して入れ直してください |
| スマホで開けない | PCとスマホが同じWi-Fiか／ファイアウォールの設定／ネットワークが「プライベート」か／設定画面で「オン」になっているか |
| スマホで「安全ではない接続」 | スマホに `rootCA.pem` を入れて信頼する設定になっているか。PCのIPが変わったら `make_lan_cert.ps1` を再実行 |
| Google連携が「接続されていません」 | 7日で切れる設定の可能性。設定画面から「Googleに接続」し直す |
| Googleへ送れなかった予定がある | 設定画面に件数が出ます。次の同期で自動的に再送します |
| マイクボタンが薄くて押せない | 「設定 > 音声入力」でモデルをダウンロードしたか。部品が入っていないと表示された場合は `setup_backend.bat` を再実行 |
| 「マイクの使用が許可されていません」 | Windowsのマイクのプライバシー設定（上記）。スマホはブラウザのサイト設定でマイクを許可 |
| 声が聞き取れないと出る | マイクの音量。話し始めが8秒以上ないと止まります |
| ウィジェットがたたまれない | 端にぴったり付いているか（少し離して寄せ直す）。入力欄にカーソルがあるとたたみません |

## 開発者向け

```bat
cd backend
.venv\Scripts\pip install pytest httpx
.venv\Scripts\python -m pytest
```

テストでは偽のLLM・偽のGoogleカレンダー・偽の文字起こしモデルを使うので、Ollama やGoogleの設定、モデルのダウンロードがなくても実行できます。

画面側（ウィジェットの自動たたみの動き）のテスト：

```powershell
cd frontend
npm test
```

### リポジトリに含めないもの

`.gitignore` で次のものは Git に入らないようにしています。予定や認証情報が外に出ないよう、これらは手で追加しないでください。

- `backend/data/`：予定のデータベース、Google の認証用JSONとトークン、LAN用の証明書、文字起こしモデル、APIキーの控え（資格情報マネージャーが使えないとき）
- `backend/.venv/`、`frontend/node_modules/`、`frontend/dist/`、`frontend/src-tauri/target/`：セットアップやビルドで作られるもの

`.bat` と `.ps1` は `.gitattributes` で CRLF のまま取り出されるので、clone したあともそのまま実行できます。

## まだ含まれないもの

- Googleのメインカレンダー以外の取り込み
- キーボードのショートカットから音声入力を始める機能
